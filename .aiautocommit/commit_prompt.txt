# IMPORTANT: Your Instructions

Generate a commit message from the `git diff` output using these rules:

#### 1. **Subject Line**
- Use a conventional commit prefix:
  - `feat`: New features (visible to users).
  - `fix`: Bug fixes, including corrections to internal behavior or error prevention.
  - `docs`: Changes only to documentation or code comments.
  - `style`: Code formatting changes (no behavior changes).
  - `refactor`: Code structure improvements with **no behavior changes** (e.g., renaming variables, extracting functions, moving code to shared components).
  - `build`: Updates to build scripts or configs.
  - `deploy`: Deployment script updates.
  - `test`: Changes to tests.
- Limit to **50 characters** after the prefix.
- Use **imperative mood** (e.g., "Extract component").
- Describe the intent or outcome succinctly.

#### 2. **Extended Commit Message**
- Include only for changes that:
  - Affect functionality (e.g., new features, bug fixes).
  - Modify build processes or deployment.
  - Have side effects or require special considerations.
- For simple refactors, style changes, or documentation updates, **do not** include an extended message.
- When included, use up to 3 markdown bullets focusing on **what changed** and **why it matters**.
- **Do not** include an extended message for:
  - Refactors that only improve code structure without altering behavior (e.g., extracting functions, renaming variables, moving code to shared components).
  - Style changes (e.g., formatting, linting).
  - Documentation updates (e.g., comments, README changes).

#### 3. **General Guidelines**
- Prioritize the purpose over listing tools or properties.
- Keep concise; avoid obvious details.
- If the change is straightforward and doesn’t affect functionality, the subject line alone is sufficient.
- Consider code comments or context only if they help determine the impact of the change.

#### 4. **Scopes**
Optional scopes (e.g., `feat(api):`):
- `api`: API endpoints, controllers, services.
- `frontend`: React components, styles, state management.
- `migration`: Database schema changes.
- `jobs`: Background jobs, scheduled tasks.
- `infra`: Infrastructure, networking, deployment, containerization.
- `prompt`: Updates to LLM or AI prompts.
