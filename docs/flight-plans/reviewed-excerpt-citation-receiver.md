# Reviewed excerpt citation receiver — Tier 2

This receiver binds each optional, closed selection to the exact reviewed source
set locked by the existing provider-context receipt. Its enumeration fingerprint
binds received source order and ordered sections, including full visit timestamps;
Core separately resolves the actual retained review time for source labels. It accepts only complete
literal quote envelopes, including the fixed limitations and provider disclaimer.
The final digest covers both selection and server-resolved identities; no caller
supplies note IDs, URLs, permissions or an accepted identity map.

The nullable JSONB expand rung is `d4de1ee4bb02`, after `3d40e4e90e05`.
It preserves legacy rows without backfill. Existing ORM and database append-only
protection covers the added column. The ID was generated by official Alembic in
an empty owned script directory using the canonical template; the real unique
head was bound statically afterward. Historical revisions import application
setup, so the normal autogenerate recipe was not invoked during preparation.

1. Require exact-head independent review, application CI, full migration graph
   and receiver/authority regression checks. The owned socket-only PostgreSQL
   rehearsal verifies the expand on its exact target table and original trigger;
   it does not substitute for a full application migration rehearsal.
2. Apply the additive rung in a reviewed staging package before starting any
   new Core web, worker or scheduler image. Older images can coexist with the
   nullable column. No account grant, delegation, capability or flag changes.
3. Deploy the receiver before the separately reviewed provider/host consumers.
   Legacy writes, request hashes and read-v1 envelopes remain unchanged when
   selection is absent. A ready authorized reviewed-source read advertises exactly
   `X-Cosmaneura-Reviewed-Excerpts: 1.0.0`; absent support keeps consumers legacy.
   The header confers no authority or review result. Read-with-citations uses 1.1.0.
4. Test actual own-provider and foreign denial, two same-day notes, exact retained
   review opening after correction, lost response/reload and exported identity
   preservation. Retained reads revalidate current own-record access and return
   the exact reviewed snapshot or deny; they never substitute current notes.
5. Consumer acceptance still requires the existing judge/parser and delivery
   gates. This receiver neither proves moral review success nor completes the
   UI, export, staging or production beta acceptance gates.

Recovery: stop the optional emitter and revert consumer/Core images as needed;
leave the expand column and accepted maps intact. Old Core safely treats newly
bound finals as stale because it cannot reproduce their new digest. Restore the
receiver to hydrate those finals again. Never drop/backfill/rebind the retained
citation column as immediate rollback. Production activation remains separate.
