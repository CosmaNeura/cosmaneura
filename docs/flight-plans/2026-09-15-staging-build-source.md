# Bounded build-source transport

Tier 2. This connects the merged candidate verifier to real bounded read-only
Git/GitHub transport and a credential-free Git archive export. It is a component
of the remaining build entry point, not another recovery platform or a completed
build/publisher/release controller. It changes no snapshot consumer, source gate,
existing CLI, workflow, identity, cloud resource or deployment policy.

The user approved scoped staging build/deployment, but this source result always
records execution/deployment authorization false. A future independently reviewed
launcher must bind actual same-task delegated-agent authorization, founder-selected
candidate, authenticated public configuration, runtime/engine, actual snapshot/
ONLINE rehearsal evidence, exact plan/command review and expiry. Hash-shaped
requests, dataclasses and a configured GitHub user do not supply those facts.
Do not impersonate human presence or reuse the human-only snapshot entry point.

## Exact source decision

- Reuse PR416's unchanged source/migration-inventory verifier. Its named human
  context is source-only: it authenticates the configured GitHub User before and
  after observations, not physical presence, Azure identity or execution permission.
- Reuse the reviewed snapshot transport's fixed Git/gh/ps pins, clean environment,
  bounded output/deadline and owned-process-group closure without changing that
  module's allowlist. The build adapter separately allows only its exact GET/Git
  read forms. No shell, fetch, token-export command, write API or workflow dispatch.
- Require the exact current protected master, configured founder identity hash,
  clean expected origin/checkout, non-shallow Git and no grafts. Retain strict
  required checks, conversation resolution, admin enforcement and Actions OFF.
- Bind the controller to its actual normal merged PR, exact Cursor review and
  successful check from the configured Cursor app (id1210556). Bind the full
  provider review object to an externally accepted exact SHA-256; COMMENTED plus
  a successful check is not a finding-free decision. The caller must actually
  accept that review and its findings/dispositions before pinning it. This
  adapter does not parse free-form prose into permission or manufacture approval.
  If upstream-only reconciliation changed its final PR
  head, all declared production bytes at the independently reviewed head, current
  master and local source must still match. Required checks bind the actual final
  PR head. This mapping does not invent a new review verdict or waive findings.
- Generate source with the fixed local `git archive --format=tar <candidate>`
  command and compare its actual bytes with the externally reviewed archive hash.
  A supplied tar's commit comment alone is not accepted as Git provenance.
  The archive process reuses PR417's bounded child owner; no source code executes.
- Bracket export with source/identity/protection checks, then perform final current
  master, origin, clean-head, identity and local-closure checks after longer review
  observations. The later build controller still owes its own phase revalidation.
- Check the complete declared local module closure for exact bytes, owner,
  non-group/world-writable regular files, no symlinks/hardlinks, bounded sizes,
  and stable device/inode/mode/owner/size/timestamps across reads. The separately
  reviewed launcher must authenticate those modules before importing them.

The existing authenticated gh child may access its configured credential store.
No token is read or returned to the controller or passed to a build environment.
Only response hashes are retained; the `/user` record returned to the verifier is
minimized to id/login/type. Raw response bytes are transient process memory, not
published review evidence. Core dumps must already be disabled before collection.
Trusted OS, same-user integrity and the existing CLI credential store remain
explicit assumptions; this is not a hostile-host sandbox or Azure-role proof.

## Limits and failure

One initial collection is bounded to180seconds, individual reads30seconds and
Git archive60seconds within that original deadline. Reads are capped at8MiB;
archive256MiB; at most2000 observations. No retries, automatic fetch, cleanup,
status writes, claims, receipts or artifact publication. A changed pin, provider
failure, incomplete review/status, source drift or ambiguous child outcome refuses.
The returned original observation time is never reset into a new authorization.
