# Staging sanitizer snapshot-to-executor binding

This Tier 2 dormant slice is based on exact protected `master` `c89af01c282622ba1bc198a17b829f90b85dcd82`. It replaces the transformer's caller-supplied evidence and row mapping with one exact sealed `AuthenticatedSanitizerSourceSnapshot`. A private keyed handoff validates the snapshot, copies only its deep-immutable typed rows, recomputes the snapshot proof over that exact copy, and binds the copy to the captured snapshot and evidence lineage before the transformer can use it. The transformer repeats snapshot and retained-evidence authentication immediately before minting its candidate.

The candidate proof uses a new domain and binds the source-snapshot contract, proof and process-local identity together with the exact evidence ancestry and transformed tables. The candidate retains the authenticated evidence and scalar snapshot-binding facts, but it does not retain the source snapshot, source rows, raw PostgreSQL frames, fragment proofs, or either HMAC key. Legacy raw-row and separate-evidence transform inputs fail closed. Equal key material remains permitted because the inventory/snapshot and transform protocols already use disjoint framed domains; independent secret provisioning is a later runtime-adapter responsibility.

This bridge adds no adapter, database, provider, filesystem, environment, network, subprocess, mutation, workflow, publication, or deployment surface. A later additive [fixed-catalog post-projection authenticator](2026-09-06-staging-sanitizer-fixed-catalog-post-projection.md) closes that proof boundary without broadening this artifact's authority. The public preflight still refuses with `activation.data_contract_executor_unimplemented`; activation remains blocked on the reviewed serializable transaction adapter with rollback, final pre-commit recheck, post-commit verification, cleanup, and bounded-failure controls. Recovery is code-only revert; no data or infrastructure rollback is needed.
