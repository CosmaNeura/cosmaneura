## Bounds and failure behavior

- Six exact source-preparation files; no capture artifacts in that catalog.
  Operator, tools, workspace, source, approvals, input namespace and distinct
  output namespace are pinned. Normal merged PR coverage must cover all sources.
- Preparation metadata expires in 30 minutes without renewal; source readback
  must ALSO remain <=10 minutes old at every start check. Neither is a firewall
  window. One shared 240-second preparation deadline and sequential sub-budgets
  never nest or reset. One process attempt shared with capture; no retry/reset.
- ForegroundConsole retains only native Terminal I/O; PreparationConsole has no
  firewall/capture methods. SnapshotConsole retains its existing capture inputs,
  confirmations, removal fallback and post-expiry closure behavior.
- Only four hashed identity fields, exact ARM response hash/times and fixed
  truthful verification flags escape. No token, username, DSN, raw app/server
  response or provider exception is printed. Credentials accessed for CLI/ARM
  are distinct from database credentials, which preparation never reads.
- Require >2430 seconds of same-token lifetime at observation production to
  cover the later session floor plus startup/preparation. Review and human delay
  need MORE lifetime. A refresh found only in the copy is still refused; no
  authority/token expiry is extended or invented.
- Public output is not a receipt or authorization. Success prints only its
  SHA256, size and false execution/deployment flags. Exclusive-write, write,
  fsync, close, source drift or expiry failure produces no success. Partial
  output remains for inspection; no overwrite/delete/claim/cleanup operation.
- Recheck actual app/rules/IP/identity during capture exactly as before. The
  preparation observations do not freeze Azure, prevent concurrent edits or
  establish native firewall expiry. Existing human 30-minute removal duties stay.
