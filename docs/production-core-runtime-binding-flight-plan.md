# Core runtime-binding prerequisite — Tier 2

This stack records a sampled binding to the accepted combined frontend/Core artifact. It grants neither provider deployment nor beta readiness.
Source preparation executed no production operation; Session Prep and the provider dual pipeline stay dark.

Founder/manual exact-current-master, applicable Terraform Apply/ancestry, provider callback, acceptance, configuration and digest gates remain.
The historical one-time caller/source fence is unchanged; promotion rebuilds or image publication are not introduced.

After canonical deploy succeeds, capture reauthenticates the successful prepare artifact and fresh public frontend configuration.
Fixed production API/worker/scheduler subscription/tenant/environment, admitted digest, source attempt revision and Procfile roles must match.
Each selected revision is sole active and ready. API traffic selects it at 100%; selected replicas are ready, with one worker and scheduler.
Old worker/scheduler replicas must drain. Inactive API replicas may finish requests without receiving new traffic.

Two matching public projections surround a fixed-origin panel fetch. Source/candidate pin SHA/SRI; system CA/hostname TLS, bounded bytes,
no redirects/auth/cookies and no ambient CA overrides are required. Inventories cap at 100 revisions/app and 100 replicas/revision.
The POSIX main-thread CLI enforces a hard five-minute alarm plus monotonic duration, restores its handler and refuses an existing timer.

All arbitrary configuration/env/secret values and private registry usernames are erased BEFORE hashing. Only constructed public structures,
env/secret-reference names and validated source process labels remain. Fingerprints cannot prove equality or validity of erased values.
Raw provider responses, secret values and their hashes never enter printed output or artifacts.

Success-only upload follows capture. Admission verifies completed successful canonical manual founder promote run/attempt, full job inventory,
ordered successful deploy/capture/upload, immutable artifact ID/GitHub archive digest, current Core source/tree/recorder and original prepare.
Both artifacts retain seven-day expiry. `check` freshly reobserves runtime/panel and current master; an authenticated old receipt is insufficient.
Persistent binding excludes pod names, allowing healthy same-revision restarts/API scaling; fresh readiness/count/drain/coherence remain required.

These facts do not prove full config equality, all served frontend assets, private DB schema/TLS, production Entra/provider DNS/TLS,
recovery rehearsal, process attestation or atomic absence of changes outside the sample. Validate required configuration, schema/TLS, Entra caller/role, provider origin/TLS and a compatible recovery pair separately.

Release source only after exact-head independent review and CI. Founder-selected prepare/promote supplies the first actual receipt; tests do not.
Capture/upload failure makes the run inadmissible without rolling back healthy apps. Resolve drift read-only before a founder-selected retry.
Source rollback removes this seam while preserving immutable evidence and existing recovery controls; no schema/config/identity/DNS changes occur.
