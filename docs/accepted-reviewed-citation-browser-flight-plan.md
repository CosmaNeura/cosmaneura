# Accepted reviewed-source browser display (Tier 2)

The browser consumes Core's fresh read 1.1 and separate retained display 1.2
through the provider's closed display bridges. A fresh link requires the exact
successful accepted final answer, turn and presentation; a restored link uses
the original retained map. Ordinals are never rebuilt by matching identical
quotes. Historical and superseded answers remain dated, display-only records;
no display field enters context/inference history.

The authenticated viewer calls only the generated retained-citation SDK route.
Core checks the current real account/record and immutable retained proof. The
browser verifies the exact reference, original section order and UTF-8 content
digest, shows visit and review clocks separately, and displays a generic denial
on missing/expired/corrupt proof. It does not substitute a current note. Record
changes, actual Clerk user/session replacement, authority transitions and focus
revalidation clear or fence old bytes. The viewer captures live Clerk identity
and verifies the SDK auth source before and after reading; retained bytes never
rebind through the shared inactive support-view status. Auth IDs stay in memory.

Deploy reviewed Core admission/display first, provider display bridges second,
and this pinned consumer last. The new delivery is ordinary script/SRI loaded
from committed reproducible esbuild bytes; its readable source and compiler
manifest live in the exact provider candidate. Old immutable browser assets
remain intact. All paths and generated additions count in the change budget.
This source proposal changes no database schema, clinical data, flags or deployment.

The tracked OpenAPI comes from the actual normal full Core407 export, with only
its three retained-citation components and GET route added. Canonical @hey-api
SDK generation, React Router typegen, full TypeScript and real DOM/Host tests
use the exact package/lock-qualified existing runtime and an owned client link.
Synthetic contract/transport/UI tests do not establish server authority or live
acceptance. Normal final-head CI and independent review remain required.

Recovery selects the prior byte-pinned consumer and provider source. The older
asset/read1.0 regressions remain unchanged in behavior. A negotiated malformed
map fails closed, canonical text stays useful, and unverified attributed export
is unavailable; no silent current-source fallback or vendor replay is allowed.

Browser account/session/loading and listener state are normalized only in the
existing Clerk configuration adapter. The viewer checks its actual mutable SDK
resource again after asynchronous digest validation, immediately before display.
The Host principal-bound mount/delegation fence is a separate dependent outcome.
