# Staging PostgreSQL server-scope evidence

`scripts/staging_server_scope_evidence.py` is a dormant, read-only prerequisite for a complete restore rehearsal. It closes the gap left by a single-database schema inventory: PostgreSQL point-in-time restore operates at server scope. The collector enumerates every `pg_database` row, including templates and platform/system databases. Every connectable database must yield a keyed schema fingerprint plus exact keyed inventories for normalized shared dependencies; extensions; foreign-data wrappers, servers, tables, options and ACLs; column ACLs/options; language ACLs; user mappings; table and PostgreSQL 16 schema publication membership; subscription worker/relation state; security labels; event triggers; and large-object metadata, ACLs, and content pages. Relation fingerprints include resolved effective tablespaces, extension records include owners, and custom collation records include owners and locale properties. View `reloptions` include `security_invoker` and `security_barrier`. A database may be unfingerprinted only when `datallowconn` is false and policy pins `connections_disabled`. Any connection or catalog permission failure on an enabled database blocks evidence; managed Azure restrictions are not waived.
Server evidence pins `pg_authid` roles/attributes and keyed password-verifier state (presence and scheme remain inside the role aggregate), memberships, per-role/database settings, database locale/owners/ACLs/default tablespaces, tablespace locations/options/ACLs, subscription definitions, prepared transactions, replication slots (including WAL status and restart/confirmed LSNs), replication origins/status, parameter ACLs, shared descriptions and security labels, and all visible `pg_settings`. Subscription `subdbid` is resolved to database name before hashing; `subskiplsn = 0/0` is canonical unset. Relation `srsublsn = 0/0` is likewise unset, while a nonzero value is captured exactly as the copy/synchronization progress boundary. New, missing, unreadable, or changed records fail closed. Numeric catalog OIDs are excluded as allocator artifacts, except large-object IDs whose referential identity must survive restore. Per-database `pg_shdepend` edges are retained as resolved object-address tuples, so owners, ACL role references, tablespaces and other shared dependencies are covered without hashing allocator OIDs. `pg_prepared_xacts`, tablespace locations, `pg_shdescription`, and replication origins are also pinned. Role and object names are policy-significant.
Raw identities, settings, password verifiers, FDW/user-mapping/subscription options, LSNs, security labels, shared descriptions, shared-dependency object names, tablespace locations, and large-object pages remain only in process memory. Evidence contains counts and domain-separated HMAC-SHA-256 digests and binds the HMAC of source resource identity, source revision, capture interval, policy digest, and owner-controlled key version. The key file must be an owner-only regular file and must never be committed. The connection string is accepted only from `STAGING_SERVER_SCOPE_DATABASE_URL`; credentials in command arguments are unsupported. Production capture accepts only explicit `host`, `port`, `dbname`, `user`, `password`, `sslmode=verify-full`, and `sslrootcert=system` libpq parameters; the sanitized connection also disables client certificates and GSS encryption so ambient identity material and GSS negotiation cannot alter authentication or bypass TLS hostname verification. Alternate routing, service files, session options, client TLS overrides, multi-host targets, ambient libpq `PG*` connection variables, and ambient OpenSSL trust-path/configuration overrides fail closed. The adapter discards the original DSN after parsing and connects with a sanitized parameter map. `allow_local=True` remains a test-only code path for an exact loopback policy target and is never exposed by the CLI.
Named server cursors enforce per-query and aggregate record/byte ceilings while iterating. A bounded aggregate preflight rejects oversized rows before they reach the client, and the streaming loop independently applies the limit to canonical uncompressed records. Queries contain no unbounded `array_agg`, and a connection cancellation timer enforces the monotonic 15-minute total deadline. A breached limit fails closed without partial evidence.
Every connectable database is captured twice in deterministic order and both keyed surface sets must match; server surfaces must also match before and after both passes. Activation must run during a coordinated freeze of DDL, role/ACL, publication/subscription, prepared-transaction, and replication-state changes so the two-pass bracket is a stable cross-database capture.
The committed policy intentionally has `activation_ready: false` and placeholder pins, so the command refuses before connecting. Activation requires a separately reviewed, trusted baseline capture with exact pins and confirmation that the Azure identity can read every required surface. This change adds no workflow, credential, database write, restore, deployment, or promotion path. The PostgreSQL connection cannot independently attest its Azure resource ID; binding the keyed receipt to authenticated control-plane evidence remains a separate activation prerequisite.
